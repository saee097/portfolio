## Getting Started

Follow these instructions to run the portfolio locally.

### Prerequisites

Make sure you have installed:

- Node.js 20 or later.
- npm.
- Git.

### 1. Clone the Repository

```bash
git clone https://github.com/saee097/portfolio.git
```

### 2. Navigate to the Project

```bash
cd portfolio
```

### 3. Install Dependencies

```bash
npm install
```

### 4. Start Development Server

```bash
npm run dev
```

Open your browser:

```text
http://localhost:3000
```

The application will be available locally with hot reloading enabled.

## Deployment

The portfolio supports two deployment options.

### 1. GitHub Pages

The primary deployment platform is GitHub Pages.

**Live URL:**

https://saee097.github.io/portfolio/

#### Automatic Deployment

The repository uses GitHub Actions to automate deployment.

Workflow:

```text
.github/
└── workflows/
    └── deploy.yml
```

Every push to the `main` branch triggers the deployment workflow.

#### One-Time GitHub Pages Configuration

1. Open the GitHub repository.
2. Navigate to **Settings**.
3. Select **Pages**.
4. Locate **Build and deployment**.
5. Set the source to **GitHub Actions**.
6. Save the configuration.

After a successful workflow execution, the portfolio is published automatically.

#### Deployment Workflow

```text
Developer
    |
    v
Git Push
    |
    v
GitHub Repository
    |
    v
GitHub Actions
    |
    v
Install Dependencies
    |
    v
Build Next.js Application
    |
    v
Deploy Artifact
    |
    v
GitHub Pages
    |
    v
Live Portfolio
```

### 2. Vercel Deployment

Vercel provides an alternative deployment option with preview deployments and custom-domain support.

**Deployment Platform:** https://vercel.com/

#### Steps

1. Open [Vercel](https://vercel.com/new).
2. Import the GitHub repository.
3. Configure the project build settings.
4. Deploy the application.
5. Connect a custom domain if required.

**Important:** GitHub Pages uses a project-specific `basePath` for this repository. Vercel deployment should use the appropriate configuration without the GitHub Pages base path.

## Configuration

### GitHub Pages Configuration

For a Next.js static export, the deployment configuration should be compatible with GitHub Pages.

Typical configuration in `next.config.ts`:

```typescript
import type { NextConfig } from "next";

const isProduction =
  process.env.GITHUB_PAGES === "true";

const nextConfig: NextConfig = {
  output: "export",

  ...(isProduction && {
    basePath: "/portfolio",
    assetPrefix: "/portfolio/",
  }),

  images: {
    unoptimized: true,
  },
};

export default nextConfig;
```

The actual configuration must match the repository's existing deployment workflow and any dynamic routes or server-side features.

### GitHub Actions Environment

If the workflow uses a dedicated GitHub Pages build configuration, make sure its environment variable and build command are consistent with `next.config.ts`.

For example:

```bash
GITHUB_PAGES=true npm run build
```
